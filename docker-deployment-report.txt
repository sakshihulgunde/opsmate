2. CONTAINERIZATION

---

Containerization is the process of packaging an application together
with its dependencies and runtime environment into an isolated,
portable container.

Containers allow applications to run consistently across different
environments because the application and its required dependencies
are packaged together.

Benefits of containerization include:

* Portability
* Faster deployment
* Environment consistency
* Process isolation
* Efficient resource utilization
* Easy scaling
* Faster application startup
* Simplified dependency management

3. VIRTUAL MACHINES VS CONTAINERS

---

A Virtual Machine emulates a complete computer and normally contains
its own guest operating system.

A Docker container shares the host operating system kernel and contains
the application and its required dependencies.

Virtual Machines:

* Include a complete guest operating system
* Generally consume more resources
* Usually take longer to start
* Provide strong hardware-level virtualization

Containers:

* Share the host kernel
* Are lightweight
* Start quickly
* Consume fewer resources
* Package applications and dependencies together

For the OpsMate project, Docker containers were selected because the
application can be packaged and deployed consistently without requiring
a complete guest operating system for every application instance.

4. DOCKER ARCHITECTURE

---

Docker uses a client-server architecture.

Important Docker components are:

Docker Client:
The Docker CLI is the interface used by the developer to send commands
to Docker.

Docker Host:
The machine where Docker Engine runs and where containers are created.

Docker Engine:
The Docker platform responsible for building and running containers.

Docker Daemon:
The background Docker service that manages images, containers,
networks and volumes.

Docker Image:
A read-only template containing the application code, runtime,
dependencies and configuration required to create a container.

Docker Container:
A running or stopped instance of a Docker image.

Docker Registry:
A repository used to store and distribute Docker images.

Docker Hub:
A public Docker registry containing publicly available images.

Amazon ECR:
AWS's private container registry used in this project to store the
OpsMate Docker images.

8. DOCKERFILE

---

The OpsMate Dockerfile uses the following required Dockerfile
instructions:

FROM
WORKDIR
COPY
RUN
EXPOSE
CMD

The Dockerfile is:

FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .

EXPOSE 5000

CMD ["python", "app.py"]

Explanation:

FROM:
Defines the base image. Python 3.12 slim was selected as the runtime
environment.

WORKDIR:
Sets /app as the working directory inside the container.

COPY:
Copies required application files from the host into the image.

RUN:
Executes commands during image creation. In this project it installs
Python dependencies.

EXPOSE:
Documents that the application uses TCP port 5000.

CMD:
Defines the default command used to start the application.

30. SECURITY

---

Security considerations implemented or considered during the project
include:

* AWS credentials should never be committed to GitHub.
* Database passwords should not be stored in public source code.
* Sensitive configuration should be excluded using .gitignore.
* ECR repositories should use appropriate access controls.
* IAM permissions should follow the principle of least privilege.
* ECS security groups should expose only required ports.
* Production applications should use HTTPS.
* Production secrets should be stored using AWS Secrets Manager or
  another secure secrets-management system.

The project avoids committing AWS credentials and other sensitive
information to GitHub.

storage usage.

* Use a small trusted base image.
* Use .dockerignore.
* Avoid unnecessary files in the build context.
* Avoid unnecessary package caches.
* Combine appropriate RUN commands where useful.
* Use multi-stage builds for larger applications.
* Keep dependencies limited to required packages.
* Regularly update dependencies.
