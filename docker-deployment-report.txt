OPS MATE – DOCKER AND AWS DEPLOYMENT REPORT
============================================

Project Name:
Containerizing and Deploying OpsMate Service Using Docker and AWS

Application:
OpsMate Service

Technology Stack:
Python, Flask, Docker, Docker Compose, PostgreSQL, Amazon ECR,
Amazon ECS, AWS Fargate, Amazon CloudWatch, Git, GitHub, Linux/Ubuntu

AWS Region:
ap-south-1


1. PROJECT OBJECTIVE
--------------------

The objective of this project was to containerize the OpsMate Flask
application using Docker and deploy the containerized application on
AWS using Amazon ECR, Amazon ECS, and AWS Fargate.

The project demonstrates the following deployment workflow:

Developer
    |
Dockerfile
    |
Docker Image
    |
Amazon ECR
    |
ECS Task Definition
    |
ECS Service
    |
AWS Fargate
    |
OpsMate Application


2. APPLICATION
--------------

OpsMate is a Python Flask web application.

The application listens on TCP port 5000.

Application endpoints:

/       - Verifies that the application is running
/health - Application health check
/db-test - Tests PostgreSQL database connectivity

The application was successfully tested inside the Docker container.


3. DOCKERFILE
-------------

The Dockerfile uses Python 3.12 slim as the base image.

Main Dockerfile operations:

- Use Python 3.12 slim base image
- Set /app as the working directory
- Copy requirements.txt
- Install Python dependencies
- Copy app.py
- Expose port 5000
- Start the Flask application

Docker image build command:

docker build -t opsmate:1.0 .


4. DOCKER CONTAINER DEPLOYMENT
------------------------------

The Docker image was used to create the OpsMate container.

Container configuration:

Container name:
opsmate-app

Port mapping:

5000:5000

The container was successfully started using Docker.

Verification command:

docker ps

The container status was verified as:

UP / RUNNING


5. APPLICATION VERIFICATION
---------------------------

The application was tested from the Ubuntu EC2 server.

Command:

curl http://localhost:5000

Result:

OpsMate Service v2 is running successfully!


Health-check command:

curl http://localhost:5000/health

Result:

OpsMate Health: OK

Both endpoints returned successful responses.


6. DOCKER LOG VERIFICATION
--------------------------

Docker logs were checked using:

docker logs opsmate-app

The logs confirmed that the Flask application started successfully
and was listening on:

0.0.0.0:5000

The following HTTP requests were successfully processed:

GET / HTTP/1.1 200
GET /health HTTP/1.1 200

This confirmed successful application execution inside the container.


7. DOCKER COMPOSE
-----------------

Docker Compose was configured to run:

- OpsMate application
- PostgreSQL database

The Compose configuration includes:

- Application service
- PostgreSQL 16 Alpine database
- Application-to-database networking
- PostgreSQL persistent volume
- PostgreSQL health check
- Application dependency on database health

The Compose configuration was validated using:

docker compose config

The configuration was successfully validated without errors.

the OpsMate Docker image.

Repository:

AWS Region:

ap-south-1

The Docker image was tagged and pushed to Amazon ECR.

The ECR image was successfully used by the ECS task definition.

15. SECURITY
------------

Sensitive configuration such as database passwords and AWS
credentials were not committed to the GitHub repository.

ECS task-definition files containing sensitive environment
configuration were excluded using .gitignore.

Production deployments should use AWS Secrets Manager or another
secure secrets-management solution instead of storing credentials
directly in configuration files.
